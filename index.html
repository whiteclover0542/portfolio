HOW I WORK

기준을 넘긴 뒤에도 강화합니다

상황 딥보이스 탐지 팀 프로젝트에서, 이미 팀이 정한 목표 성능(목표치)에 도달한 상태였습니다.

행동 목표치를 채웠다고 끝내지 않고, 더 나은 결과를 위해 계속 점검하고 다듬으며 끝까지 파고들었습니다.

결과 목표치를 넘어 EER 0.98%까지 판별 성능을 끌어올렸습니다.

EER(Equal Error Rate, 동일오류율)은 낮을수록 판별 성능이 뛰어납니다. 학습 데이터를 늘려 가며 36.00%였던 EER을 0.98%까지 낮췄습니다.

결과를 의심하고 직접 검증합니다

상황 PetLoss Care AI 팀 프로젝트에서, 결과물을 완성한 상태였습니다.

행동 완성됐다고 끝내지 않고, 검증표·결과지표·성능표를 통합해 만들고 골든셋(golden set)과 G-Eval 같은 방법으로 직접 테스트·검증하며 부족한 점을 찾아 보완했습니다.

결과 놓쳤던 오점들을 미리 발견해 고칠 수 있었습니다.

검증표·성능표와 골든셋으로 테스트해, 목표를 통과한 지표와 놓친 지표를 함께 찾아냈습니다. G-Eval은 일관성·유용성·자연스러움·윤리 준수 네 항목 모두 목표(4.0 이상)를 넘었습니다.

  • G-Eval 평균 4.6~4.8점 (목표 4.0점 이상) 통과
  • 위기 감지 정확도 40/40건, 100% (목표 90% 이상) 통과
  • WER · 1인칭 19.1% (목표 15% 이하) 초과 → 발견 후 개선
  • 테스트셋 40문항 중 위험 신호 9건(22.5%)을 위기 감지 검증용으로 구성

작업 상태를 구조화합니다

상황 팀 프로젝트에서 크고 작은 변경 사항이 계속 생기는 상황이었습니다.

행동 프로젝트 진행 상황을 Start → In Progress → Review → Done → Blocked 상태로 구분해 항상 정리하고 공유했습니다.

결과 헷갈리거나 빼먹는 것 없이 순서대로 일을 진행할 수 있었습니다.

실제 팀 프로젝트에서 시작 전·진행 중·리뷰 중(PR)·완료·막힘 상태를 색으로 구분한 진행 상태표를 만들어, 팀원들도 한눈에 진행 상황을 파악할 수 있게 관리했습니다.

  • 상태 표기 체계 시작 전 → 진행 중 → 리뷰 중(PR) → 완료 → 막힘(blocked) 5단계로 색상 구분해 관리
  • 진행률 추적 공통 기반 8/8 · 프로토타입 8개 기능 8/8 · 멀티모달(가산점) 4/4, 영역별 표로 한눈에 파악
  • 완료 아카이브 담당 프롬프트 6개 파일을 검토 결과와 함께 동결(2026-06-15) 처리해 이력 추적 가능
