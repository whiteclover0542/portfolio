## 짧은 확인 방법
1. **어디로**: https://whiteclover-portfolio.vercel.app
2. **3단계**: 주소 접속 → PRIVATE 구역에 아이디 입력 후 "패스키 등록" → 기기 인증 완료 시 비공개 메모·패스키 목록이 바로 열림
3. **통과 기준**: 로그인 전엔 비공개 메모가 전혀 안 보임 + 비밀번호 입력 칸이 없음
4. **안 될 때**: 패스키 미지원 브라우저면 안내 문구가 뜨고, 취소하면 잠긴 상태 그대로 유지(서버에 아무것도 안 남음)

## AI와 내 판단 3줄
- **AI에게 맡긴 일**: WebAuthn(SimpleWebAuthn) API 구현, Vercel+Redis 배포, Playwright로 등록·로그인·챌린지 재사용·기기 분실·교차 계정 시나리오 자동 검증
- **내가 직접 판단한 일**: 인증 서버 구성(Vercel+Redis), 더미 데이터·계정 모델, "아직 못 막은 것"으로 무엇을 인정할지, Vercel/GitHub 로그인, 실제 기기로 패스키 등록해 저장 위치(삼성패스) 확인
- **AI 말을 따르지 않은 일**: 없음 — 제안을 그대로 채택하되 매번 자동화 테스트로 직접 재검증 후 반영

## 인증 구현 설명서

**① 무엇으로 붙였나** — `@simplewebauthn/server`(백엔드) + `@simplewebauthn/browser`(프런트) 라이브러리. challenge/세션 저장소, 데이터 모델, API 엔드포인트는 직접 구현. 실제 갤럭시 기기로 등록해보니 **삼성패스**에 저장됨.

**② 왜 그걸 골랐나** — WebAuthn을 직접 구현하면 서명 검증 등에서 실수하기 쉬워 검증된 오픈소스에 맡기고, 저장·세션·API는 직접 설계. GitHub Pages(정적)에서 Vercel(서버리스)+Upstash Redis로 옮겨 challenge 발급·검증을 서버에서 처리.

**③ 어디를 고쳤나**
| 흐름 | 위치 |
|---|---|
| 등록 | `api/register-options.js` → `api/register-verify.js` |
| 로그인 | `api/login-options.js` → `api/login-verify.js` |
| 로그아웃 | `api/logout.js` |
| 비공개 조회 | `api/private.js`, `api/passkeys.js` (둘 다 세션 쿠키의 username만 신뢰, `api/private.js:10-13`) |

**④ 안 열리는 것 확인** (전체 요청/응답: [evidence-prod/log.md](evidence-prod/log.md))
- 로그인 없이 `/api/private` → 401
- 남의 패스키로 로그인 시도(양방향) → 401 "이 계정에 등록된 패스키가 아닙니다"
- 성공한 로그인 요청 재전송(challenge 재사용) → 401 "이미 사용됨"
- 삭제된 패스키 id로 로그인 → 401, 남은 패스키로는 성공

**⑤ AI와 나** — 위와 동일

**⑥ 아직 못 막은 것** — `login-options`가 계정 존재 여부에 따라 404/200을 다르게 반환해 아이디 열거(username enumeration)가 가능하고, rate limit도 없음.
